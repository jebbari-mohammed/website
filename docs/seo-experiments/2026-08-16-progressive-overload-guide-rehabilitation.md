# SEO Experiment: Progressive Overload App Guide Rehabilitation

- **Status:** launched
- **Launch date:** 2026-08-16
- **Target URL:** https://youraicoach.life/blog/best-app-to-track-progressive-overload-automatically
- **Action class:** evidence-backed content rehabilitation / re-indexing
- **Owner:** ChatGPT senior SEO lead

## First-party evidence

The 2026-08-16 Search Console health run returned 25 query + landing-page rows, 33 impressions, and 0 clicks for 2026-07-19 through 2026-08-15. The public workflow keeps exact query strings encrypted.

The prior private exact-query review identified this existing URL as the strongest content-side rank-leverage candidate on the site. The page was receiving Google visibility while still quarantined with `noindex`, so the opportunity is to rehabilitate the existing URL rather than create a competing new page. Exact query strings and private query/page metrics are intentionally not committed to this public repository.

## Pre-change state

The page was excluded from search with both `robots=noindex` and `googlebot=noindex`, carried a legacy quarantine marker, and contained unsupported first-person anecdotes, unsourced superlatives, blanket automation claims, and an FAQ that overstated what AI fitness apps can determine. It also linked hreflang alternates to untranslated/quarantined variants.

The canonical URL itself is preserved because Google already associates search visibility with it.

## SERP rationale

The current search landscape for progressive-overload apps includes:

- specialist app/product pages built around explicit progression behavior;
- comparison pages that define a progression-specific methodology before ranking products;
- first-party product documentation explaining how past performance becomes a next-session recommendation.

The strongest results answer the decision task directly: what is logged, what target is generated, what happens after a miss, and whether progression follows a transparent scheme or an adaptive system.

## Change

The page was rebuilt around the original **IZEM LOAD test**:

1. **Last performance** — is prior performance visible when training?
2. **Objective next target** — does the product produce a concrete target?
3. **Adjustment rule** — what happens after a miss or interruption?
4. **Decision clarity** — can the user understand the progression rule?

The rehabilitation also:

- removes both `noindex` directives and the legacy quarantine marker;
- preserves the existing canonical URL and publication date;
- removes unsupported personal anecdotes and fabricated testing language;
- replaces blanket “IZEM is best” claims with a transparent task-based comparison;
- adds a browser-only LOAD scorecard for evaluating any app;
- compares only behavior documented in official product pages or official app-store listings;
- explicitly states that competitor products were not hands-on tested by IZEM;
- links primary sources and dates the feature check;
- removes hreflang references to still-quarantined translated variants;
- adds a careful safety boundary and an authoritative ACSM resistance-training source;
- positions IZEM honestly as a broader coaching system with progressive-overload support, not as a dedicated automatic next-weight calculator.

## Cannibalization review

No new URL is created. The existing URL is rehabilitated in place. Nearby IZEM pages serve different intent:

- `/izem-ai-fitness-coach/` — canonical product/entity explanation;
- `/blog/ai-personal-trainer-that-actually-works` — broader AI-coach evaluation framework;
- `/blog/gym-machines-vs-free-weights` — equipment-choice intent;
- `/workout-consistency-calculator/` — planned-versus-completed consistency calculation.

## Hypothesis

Rehabilitating and re-indexing an existing URL that Google is already testing will produce more useful search visibility than adding another cold-start URL, because the page now matches the progressive-overload app comparison task with a transparent methodology, primary-source evidence, and a concrete interactive tool.
